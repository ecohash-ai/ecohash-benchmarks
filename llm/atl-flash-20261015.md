# DeepSeek V4 Flash and Qwen3.8 Flash Next on RTX PRO 6000

Measured in ATL on 2026-10-15. DeepSeek used eight GPUs on one node; Qwen used four on another. Both used NVIDIA RTX PRO 6000 Blackwell Server Edition GPUs, 96 GB class, over PCIe. Requests originated on the bastion's `127.0.0.1` and reached each model Pod through `kubectl port-forward` to port 8000. This bypasses the Ecolink public API, regional gateway and their authentication. Timings include the bastion-to-cluster forwarding path. Only text was tested.

## Complete-answer test

The main test used the eight short questions from `capacity_test.py`, twice each, at C=1. Topics include coding, CAP, hashing, memoization, HTTP and database normalization. Corpus SHA-256: `cd930af0d7b0415cd46e3db4105ad34e3731111bf23a056cc6fcb0332ef4bcdc`. Two warmups were excluded. The output cap was 4096, with native completion usage including reasoning; all 16 measured requests per model ended normally with answer text. Seed was not fixed.

TTFT ends at the first reasoning or answer token. Per-request decode speed is `(completion_tokens - 1) / decode_seconds`; the table reports its median. Aggregate throughput divides all successful output tokens by the measured window. E2E covers request send to stream completion. MTP can emit several tokens per SSE chunk, so chunk count is not used as a token count.

TPOT is the per-request average decode time per output token after the first token; P50/P95 are percentiles across requests. TPM below means output tokens per minute, calculated as aggregate output tokens/s times 60. It excludes input tokens and is a rate normalized from the measured window, not a platform quota or a sustained capacity claim.

| Metric | DeepSeek | Qwen |
|---|---:|---:|
| Actual input tokens, min / p50 / max | 107 / 113.5 / 117 | 88 / 92.5 / 98 |
| Actual completion tokens, min / p50 / max | 217 / 486.5 / 1079 | 258 / 348.5 / 1052 |
| Decode speed p50 | 161.33 tok/s | 193.36 tok/s |
| Aggregate output speed | 156.88 tok/s | 181.76 tok/s |
| TTFT p50 / p95 | 140.00 / 206.93 ms | 98.56 / 100.09 ms |
| TPOT p50 / p95 | 6.20 / 7.22 ms | 5.17 / 5.99 ms |
| E2E p50 / p95 | 2.983 / 6.165 s | 2.149 / 5.331 s |
| Completed requests/min | 17.39 | 23.94 |

| Measured window | 55.20 s | 40.09 s |
| Complete answers / failures / request OOM | 16 / 0 / 0 | 16 / 0 / 0 |

About 1K completion tokens took 6.76 s for DeepSeek and 5.29 s for Qwen, with TTFT of 139 ms and 97 ms. Generation length explains much of the E2E tail. These 16-request samples do not establish a sustained service rate or a tail-latency guarantee.

The download stage runs from the timestamped `download_start` event to `download_complete`, including shard-size verification. Full Job time also includes scheduling, container startup, dependency installation and metadata requests. These observations do not isolate network transfer time or count actual network bytes.
